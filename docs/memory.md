## 2026-10-18. Режим permissions по умолчанию — обоснование
- Политика в `.claude/settings.json` (`permissions`), три уровня, принцип: **минимум прерываний на безопасном цикле, человек — единственный одобряющий на необратимых границах**.
- **allow** — только безопасное и проверяемое: гейты качества (`lint/check/format/build/test`), git-чтения + `git add`/`commit` (локальное, обратимо) — цикл «правка→проверка» не тонет в диалогах.
- **ask** — `git push`: единственная публикающая операция наружу; внешнее действие — всегда с подтверждением владельца.
- **deny** — необратимое и секретное: `Read/Bash-обёртки` на `.env` (секреты агенту недоступны даже по оплошности; проверено реальной блокировкой), `rm -rf` (каскадное уничтожение).
- **Осознанные компромиссы** (не дыры, а границы политики): `rm -r` без `-f` проходит обычный prompt; обфусцированный доступ к секретам (`sed`/`base64`-обёртки) deny-правилами не покрывается — компенсируется договором агента; `npm install` не в allow — supply-chain меняется осознанно.
- Связка: `docs/about.md` — доказательства работы среды (скрины блокировки .env и зелёных тестов).
