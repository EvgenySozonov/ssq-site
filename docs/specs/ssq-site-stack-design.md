# Спека: сайт «Умный квадрат» (SSQ-site)

- Дата: 2026-10-17. Статус: на ревью владельцем.
- Источник решений: диалог 2026-10-16 (лог — [../memory.md](../memory.md)); визуальные вариации — `.superpowers/brainstorm/`.
- Связанные документы: [product.md](../product.md), [architecture.md](../architecture.md), [design.md](../design.md), [plan.md](../plan.md). Спека не дублирует их — фиксирует контракт реализации.

## 1. Цель и границы

Разработать многостраничный сайт компании «Умный квадрат» (электромонтаж + умный дом) с реальной приёмкой заявок. Каркас обязан допускать добавление новых направлений услуг без правки кода роутинга.

**В объёме первого релиза:** каркас, главная, направления услуг (2 шт.), услуги, цены, портфолио (пустое пока), о компании, контакты + форма → Telegram, политика ПДн, deploy.

**Вне объёма первого релиза (YAGNI):** блог (роуты готовит каркас), калькулятор (роут готовит каркас), CRM-интеграции, личные кабинеты, мультиязычность, отзывы (компонент скрывается при пустых данных), dark-mode-переключатель (тема одна).

## 2. Стек

| Слой | Выбор |
|---|---|
| Фреймворк | Astro (SSG) |
| Интерактив | React-острова по месту, иначе ноль JS |
| Язык | TypeScript, strict |
| Стили | Tailwind CSS v4; токены — CSS-переменные |
| Контент | Astro Content Collections: MDX (портфолио, блог) + JSON (services, pricing, reviews) |
| Форма | Python 3 CGI-скрипт (только stdlib) на Beget Shared |
| Деплой | `astro build` → rsync по SSH, скрипт `deploy.sh` |
| Git | приватный GitHub; проверка = `astro build` + Prettier |

Ограничение, которое определяет выбор: Beget Shared не умеет Node → в проде только статика + CGI. Fullstack-фреймворки (Next) отклонены (лог решений, 2026-10-16).

## 3. Карта маршрутов

```
/                              главная
/services/                     обзор направлений
/services/[line]/              посадочная направления
/services/[line]/[service]/    услуга внутри направления
/portfolio/                    работы, фильтр по направлению (React-остров)
/portfolio/[slug]/             кейс (MDX)
/pricing/                      цены
/calculator/                   калькулятор — позже, роут-заглушка
/about/                        о компании
/reviews/                      отзывы — позже, роут-заглушка
/blog/ + /blog/[slug]/         блог — позже, роут-заглушки
/contacts/                     контакты + форма
/legal/privacy/                политика ПДн (обязательна к релизу формы)
/404                           оформленная 404
```

Правило каркаса: `/services/[line]/...` генерируется циклом по `lines.json`. Тест добавляемости: добавление строки в `lines.json` собирает новый раздел без правки любого кодового файла (сценарий — [test-case.md](../test-case.md), шаг 1).

## 4. Модель данных

### 4.1 `src/data/services/lines.json` — направления (единый источник разметки услуг)

```json
[
  {
    "slug": "elektromontazh",
    "title": "Электромонтаж",
    "tagline": "Разводка, щиты, освещение — проект и монтаж под ключ",
    "order": 1
  },
  {
    "slug": "umniy-dom",
    "title": "Умный дом",
    "tagline": "Автоматизация освещения, климата и сценариев",
    "order": 2
  }
]
```

Схема zod: `slug` (kebab-case, латиница), `title`, `tagline`, `order`; slug уникален.

### 4.2 `src/data/services/<line>.json` — услуги направления

```json
[
  {
    "slug": "razvodka-elektriki",
    "title": "Разводка электрики",
    "summary": "Скрытая разводка по проекту с фотофиксацией каждого этапа",
    "priceFrom": 0,
    "order": 1
  }
]
```

- `priceFrom: 0` = «цена по смете» (на публичной странице — «по смете», цифра выводится только при > 0). Правило честного копирайтинга: без подтверждённой цены — заглушка «по смете».
- Страницы услуг первого релиза — генерируются из JSON; расширенный контент услуги (текст, галерея) — в следующей итерации, в JSON добавляется поле `body` (md-путь) опционально.

### 4.3 Коллекция `portfolio` (MDX)

Frontmatter-схема: `title`, `line` (enum по slugs из lines.json), `date`, `photos` (массив путей), `summary`, `published: boolean`. Кейсы с `published: false` не попадают в маршруты — на старте коллекция пуста, фильтр и секция главной скрываются.

### 4.4 Коллекция `blog` (MDX) — подготовлена схемой, контент позже.

Frontmatter: `title`, `description`, `date`, `tags` (строковый массив), `published`.

### 4.5 `src/data/pricing.json`, `reviews.json`

- `pricing.json`: группы позиций `{ group, items: [{ name, unit, priceFrom, note? }] }`.
- `reviews.json`: `{ author, text, date, published }` — секция главной рендерится только при непустом массиве.

### 4.6 `src/data/site.json` — единственный источник контактных данных

`{ phone, email, address, workingHours, telegram }` — футер, контакты, эндпоинт формы и микроразметка берут отсюда; сейчас — осмысленные заглушки, без хардкода в компонентах.

## 5. Дизайн-система

Токены в `src/styles/tokens.css` (полный перечень — [design.md](../design.md)):

```css
:root {
  --color-bg: #101014;
  --color-surface: #17191d;
  --color-text: #eceae6;
  --color-text-muted: #9a9a9a;
  --color-accent: #c9a15a;         /* медь: кнопки, цифры, подчёркивания */
  --color-accent-contrast: #101014;
  --color-line: #2a2d33;
  --font-display: 'Lora', Georgia, serif;        /* заголовки */
  --font-sans: 'Manrope', system-ui, sans-serif; /* текст/UI */
  --font-mono: 'JetBrains Mono', ui-monospace, monospace;
  --radius-s: 2px;                  /* карточки/кнопки — почти прямые */
  --border-accent: 3px solid var(--color-accent);  /* левый бордер карточек */
}
```

- Шрифты — Google Fonts с полной кириллицей, `font-display: swap`, локальный фоллбек-стек обязателен.
- Анимации — `@media (prefers-reduced-motion: reduce)` отключает всё.
- Контраст: `--color-text-muted` на `--color-bg` — проверяется на AA (qa.md).
- Hero: full-bleed фото + градиент затемнения; до реальных фото — бронзовый градиент-фоллбек по цепочке, аналогично референсу `.hero__bg`.
- Секции «Работы»/«Отзывы» главной скрываются при пустых данных (о решении — content/strategy.md).

## 6. Форма заявки — контракт

### 6.1 Клиентская часть (`/contacts/` + CTA-секции)

Поля: имя (обяз.), телефон (обяз., маска формат РФ), комментарий (оп.), чекбокс согласия на обработку ПДн (обяз., ссылка на `/legal/privacy/`). Honeypot поле `website` — видим только ботам. `novalidate`, собственная подсветка ошибок (паттерн референса). Состояния: idle → sending → ok (успех, форма сбрасывается) / error (текст ошибки + телефон из `site.json` как альтернативный канал).

### 6.2 Эндпоинт `cgi-bin/contact.py` (Beget, Python 3, CGI)

- Только stdlib: CGI на голом Python (не Passenger) — `.htaccess` с `AddHandler cgi-script .py` + `ExecCGI`.
- Метод `POST`, принимает `application/json` или form-encoded.
- Отклоняет: пустые обязательные, телефон, несогласие с чекбоксом — ответ `400 {ok:false, error:"..."}` (текст ошибки — русский, дружелюбный).
- Отправки с заполненным honeypot «успешны для клиента», но не доставляются (`{ok:true}` silently).
- Rate-limit: по IP, `FORM_RATE_LIMIT_PER_HOUR` (по умолчанию 10/ч), хранение — файл-счётчик в `/tmp`.
- Доставка: POST в Telegram Bot API (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`); время ожидания 5 с, при отказе — не маскирует успех, отвечает `502 {ok:false}`.
- Секреты — вне docroot: `/home/<user>/.env-ssq` (путь через `SSQ_ENV_PATH`), переменные окружения имеют приоритет; в репозитории — `.env.example`.
- Развитие: подключение CRM = замена тела доставки, контракт ответа не меняется.

### 6.3 Юридическая обвязка

- Чекбокс согласия обязателен; политика на `/legal/privacy/` называет оператора (ИП, реквизиты — после регистрации, см. content/strategy.md).
- Форма без политики/реквизитов не выкатывается (qa.md).

## 7. SEO

- `<title>`/`description` — свой на каждой странице; шаблон: `<Страница> — <Направление> — Умный квадрат`.
- Sitemap (интеграция), robots.txt, canonical только на `smart-square.ru`; `smart-sq.ru` — 301 на основной (на стороне Beget/DNS — задача владельца, зафиксировано).
- Open Graph: `og:title`, `og:description`, `og:image` (og-default), `og:type` на статических страницах.
- schema.org: `LocalBusiness` на главной (из `site.json`), `Service` на страницах направлений/услуг.
- `<html lang="ru">`.

## 8. Деплой и окружение

- Beget Shared: SSH включён; исполнение CGI `.py` — включить/проверить в панели до шага 6 (тест — Task 7, шаг 5).
- `deploy.sh`: сборка `astro build`, rsync `dist/` (включая `cgi-bin/contact.py` и `.htaccess`) → корень сайта; секретный файл `.env-ssq` на сервере — вручную один раз, rsync его не трогает.
- Домены: основной `smart-square.ru`; `smart-sq.ru` — 301-редирект.
- Rollback: через `rsync --backup --backup-dir` — перед выкатом содержимое docroot складывается в удалённый каталог `~/releases/backup-<timestamp>/`; откат = обратный rsync из backup. Симлинки неприменимы: docroot Beget Shared фиксирован, каталог-симлинк сломает путь сайта.

## 10. Порядок реализации

13 шагов с чек-листом статуса — [../plan.md](../plan.md). Порядок: каркас → главная → контакты/форма (kpi-функция, раньше дизайна услуг) → направления услуг → цены → портфолио → о компании → отзывы → юрстраницы → деплой → фото → блог → калькулятор.

Зависимость, которую фиксирует спека: форма (шаг 3) не выходит в прод раньше реквизитов ИП и политики (шаг 9, частично опережает порядок — политика входит в объём шага 3).

## 11. Риски

1. **Нет реальных фото** — full-bleed hero деградирует на градиент; съёмка (шаг 11) обязательна до финала.
2. **ИП не оформлен к шагу 3** — форма готова, но не выкатывается; политика ПДн требует реквизитов.
3. **Beget Shared без Node** — осознанное ограничение; при появлении задач, которым нужен Node (интеграции CRM сложнее вебхука), пересматривать хостинг (VPS).
4. **Отзывы/кейсы пусты на релизе** — предусмотрено: блоки скрываются, сайт не выглядит пустым за счёт hero + стандартов + процесс.
