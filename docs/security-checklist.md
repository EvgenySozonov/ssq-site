## 7. Открытые риски из CONCERNS.md (проверять статус на каждом релизе)

Закрытие/принятие каждого — решение владельца. Статусы на 2026-10-29:

- [x] `X-Forwarded-For` спуфится → rate-limit обходится. **Закрыто 2026-10-29**: `client_ip()` резолвит правую публичную запись XFF за приватным REMOTE_ADDR, левые (клиентские) записи игнорируются; публичный `REMOTE_ADDR` — клиент напрямую. Тесты: `test_contact.py` «rightmost_public_ip / spoofed_left».
- [x] Нет проверки `Origin`/`Referer`. **Закрыто 2026-10-29**: строгий гейт в `origin_violation()` (пустой/чужой → 400); переопределение для отладки — `SSQ_FORM_ALLOWED_ORIGINS`. Тесты: `OriginGateTest` (5 кейсов).
- [x] Нет лимитов длины полей. **Закрыто 2026-10-29**: name ≤ 100, comment ≤ 1000 на сервере (400, дружелюбный текст) + `maxlength` на клиенте. Тесты: `LengthLimitTest` (4 кейса).
- [x] `/tmp` недоступен → rate-limit молча исчезает. **Принято 2026-10-29** (fail-open сохранён: заявки не блокируем) + предупреждение в stderr → error-log Beget (не молча). Тест-док: stderr-сообщение «rate-limit counter unavailable».

Осторожно при деплое: строгий Origin-гейт может отрезать легитимные запросы экзотических клиентов (прокси, режущие Referer) — отследить после первого выката по отчётам (заявки «не отправляются» без явной ошибки).
