# Глобальные проверки (каждая итерация)

1. `astro check` типы-чистый и `astro build` проходит без ошибок — сломанный контент/ссылка/тип = невыполненный пункт. Скрипт-контракт: в целевом `package.json` (в `site/`, создаётся на шаге 1 каркаса) — `"check": "astro check"`; гейты вызывают `npm run check`.
2. `npm run lint` (ESLint, решение 2026-10-18 в [memory.md](memory.md)) — без ошибок; замечания a11y-правил в шаблонах не глушить без причины.
3. `npm test` (vitest) — зелёный: zod-схемы данных, формат цены, инварианты `lines.json`. Обязателен перед коммитом любого изменения в `site/src/lib/` и `site/src/data/`.
4. Все страницы из карты маршрутов ([architecture.md](architecture.md)) открываются, 404 — оформленная.
5. Мобильная вёрстка (ширина ~400px) не даёт горизонтального скролла.

# Рутина, снятая с рук автоматически

- vitest покрывает lib-слой; TDD-порядок (тест до кода) — при изменениях в `site/src/lib/`.
- Playwright MCP — сценарии UI-приёмки (шаг Task 12 плана, после каждого релиза): отсутствие h-скролла на 400px, навигация по страницам, error-ветка формы, FAQ-аккордеон, скриншоты финальной приёмки. Правило: ручная проверка «увидеть глазами» остаётся за владельцем по скриншотам, а не по живому сайту.
- claude-security:scan — перед первым и каждым последующим релизом; CONFIRMED-находки = блокер выката.

# Форма (критичная функция — проверять каждый раз после правок)

1. Пустые обязательные поля — подсветка, отправки нет.
2. Заполненная форма с чекбоксом согласия — заявка приходит в Telegram.
3. Без чекбокса согласия — отправка блокируется.
4. Honeypot: заполненное скрытое поле — заявка не доставляется, ответ маскируется под успех.
5. Повторные отправки с одного IP чаще лимита — отклоняются.
6. Эндпоинт недоступен — пользователь видит ошибку и телефон, а не «тихую» потерю заявки.
