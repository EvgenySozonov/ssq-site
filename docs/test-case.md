# Сценарии

## Шаг 1. Каркас
- Открываются `/`, `/services/`, `/services/elektromontazh/`, `/services/umniy-dom/` — последние два собраны из одного шаблона по `lines.json`, тексты различаются.
- В `lines.json` добавлено тестовое третье направление → `/services/test/` собирается без правки кода → тестовая запись удалена.

## Шаг 2. Главная
- Секции идут в порядке из design.md; на 400px — вертикаль без скролла по горизонтали.
- Секция «Работы» тянет 3 последних кейса из коллекции, а не захардкоженный список.
- FAQ раскрывается/закрывается без JS-острова, работает с клавиатуры.

## Шаг 3. Контакты + форма
- Отправка формы с реального устройства → сообщение в Telegram в течение секунд.
- Ошибка эндпоинта → виден телефон, не «тишина».
- Honeypot и лимиты — по сценариям из qa.md.

## Шаг 4. Направления услуг
- `/services/elektromontazh/` и `/services/umniy-dom/` визуально одного шаблона, контент из JSON.
- Страница услуги перелинкована с кейсами направления.

## Шаг 6. Портфолио
- Фильтр по направлению работает; кейс открывается с полными фото и метками.

## Автоматический прогон (Task 12 плана)

- vitest: `npm test` — зелёный до приёмки.
- Playwright: h-скролл на 400px, навигация, error-ветка формы, FAQ — сценарии в плане Task 12, шаг 3.

## Шаг 10. Деплой
- `git push` → `deploy.sh` → сайт открывается с домена Beget, форма из прода доставляет заявки.
- `.env` с токеном отсутствует в репозитории (проверка: поиск по истории git).

## Шаг 11. Фото
- Full-bleed hero с реальным фото; на медленной сети сначала градиент, фото дорисовывается без сдвига текста (CLS ≈ 0).
