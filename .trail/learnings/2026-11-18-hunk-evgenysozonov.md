Расщепление правок файла между двумя коммитами: hunk-фильтр — патч на индекс И рабочее дерево

## Decided
Правка одного файла распадается на два логических изменения (SSQ README, 2026-11-18): git diff > патч → фильтр хунков по маркеру в добавленных строках → git restore файла → git apply --cached ОТФИЛЬТРОВАННОГО патча и git apply этого же патча на рабочее дерево → коммит. Рабочее дерево после этого содержит только второе изменение, и следующий git add файла не перетирает частично закоммиченное.

## Tried and ruled out
Применять отфильтрованный патч только на индекс (--cached) без синхронного apply на рабочее дерево — отклонено, проверено на практике: git restore откатил файл к полной старой версии, следующий git add записал в коммит старый контент и вытер уже закоммиченные изменения (регрессия, поймал коммит b462653, откатил 3b49649).

## Watch out
После частичного стейджинга НЕ делать git add файла, чьё рабочее состояние осталось на pre-change версии: сначала сверить рабочее дерево с индексом по нужным хункам (git diff HEAD -- файл пустой по отфильтрованным маркерам). Фильтр — по содержимому добавленных строк, не по позициям хунков.
