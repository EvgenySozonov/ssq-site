# Конвенции Astro-каркаса SSQ-site

Источники решений: `docs/architecture.md` и `docs/specs/ssq-site-stack-design.md` —
они главнее этого скилла; скилл — оперативная выжимка, правится вместе с ними.
Если скилл и докс расходятся — править оба и сказать владельцу о расхождении.

## Почему каркас именно такой

Beget Shared не умеет Node в рантайме → прод = только статика + CGI. Поэтому
Astro SSG + React-острова по месту, иначе ноль JS. Fullstack-фреймворки
(Next и пр.) отклонены (docs/memory.md, решение «стек A»).

## Каркас маршрутов

- Роут `/services/[line]/...` строится циклом по `src/data/services/lines.json`, а не
  файлами на каждое направление. Добавление направления = новая запись в
  `lines.json`, ноль правок кодовых файлов. Каждая правка роутинга, которая
  требует правки кода при добавлении направления, — нарушение каркаса.
- Тест добавляемости (спека §3): добавление строки в `lines.json` собирает
  новый раздел без правки любого кодового файла.
- Карта маршрутов — в `docs/architecture.md`. `/calculator/`, `/reviews/`,
  `/blog/` — роут-заглушки, контент позже.
- 404 — оформленная (`/404`), не дефолтная.

## React-острова

- Интерактивность — React-островом только там, где нужна интерактивность
  (калькулятор, фильтр портфолио). Всё остальное — ноль JS.
- Каждый остров должен быть обоснован: назови, какая интерактивность его
  требует, до его создания.
- Острова живут в `src/components/react/`; правила типизации —
  в скилле `.claude/skills/ssq-typescript-strict/SKILL.md`.

## Данные

- Активные данные (телефон, адрес, соцсети) — в data-файлах, не в компонентах.
- `src/data/site.json` — единственный источник контактных данных; футер,
  контакты, эндпоинт формы и микроразметка берут отсюда. Хардкод контактов
  в компонентах — баг.
- `lines.json` — единый источник разметки услуг (§4.1 спеки): `slug`
  (kebab-case, латиница, уникален), `title`, `tagline`, `order`; zod-схема.
- `<line>.json` — услуги направления: slug, title, summary, priceFrom, order.
  `priceFrom: 0` = «по смете» — цифра выводится только при > 0.
  Правило честного копирайтинга: без подтверждённой цены — «по смете».
- `pricing.json`: группы `{ group, items: [{ name, unit, priceFrom, note? }] }`.
- `reviews.json`: `{ author, text, date, published }`; секция главной рендерится
  только при непустом массиве непублинованных записей.
- Секции «Работы»/«Отзывы» главной скрываются при пустых данных.

## Контент-коллекции (MDX)

- `portfolio`: `title`, `line` (enum по slugs из lines.json), `date`, `photos`,
  `summary`, `published`. Кейсы с `published: false` не попадают в маршруты.
- `blog`: `title`, `description`, `date`, `tags`, `published` — схема
  подготовлена, контент позже.
- Frontmatter-схемы — zod, в `src/content/config.ts`.

## Дизайн-токены

Токенизация, палитра «Ночная медь», типографика, анимации и доступность —
в скилле `.claude/skills/ssq-tailwind-tokens/SKILL.md`. Кратко: все design-значения
проходят через `src/styles/tokens.css`, в компонентах не хардкодить.

## SEO

- `<title>`/`description` — свой на каждой странице; шаблон:
  `<Страница> — <Направление> — Умный квадрат`.
- Canonical/sitemap — только smart-square.ru; smart-sq.ru — 301.
- schema.org: `LocalBusiness` (из site.json) на главной, `Service` на
  страницах направлений/услуг. `<html lang="ru">`.

## Проверки перед завершением (qa.md)

1. `npm run lint` (ESLint) без ошибок — решение 2026-10-18 в docs/memory.md;
   a11y-замечания в шаблонах не глушить без причины
2. `astro check` типы-чистый и `astro build` проходит без ошибок; типы —
   `npm run check` (контракт скрипта в qa.md, живёт с шага 1 каркаса)
3. vitest зелёный (zod-схемы, инварианты `lines.json`) — обязателен при правке
   `src/lib/` и `src/data/`
4. Все страницы карты маршрутов открываются; 404 оформленная
5. на ~400px нет горизонтального скролла
6. после правок формы — чек-лист формы из qa.md целиком
