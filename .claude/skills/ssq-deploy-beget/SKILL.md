# Деплой SSQ-site на Beget Shared

Источники решений: `docs/specs/ssq-site-stack-design.md` (§6.2, §8) и
`docs/architecture.md`. Докс главнее скилла; при расхождении — править оба.

> Примечание: в спеке нет отдельного файла deploy-документации; скилл — первая
> выжимка. Держать в синхроне со специ.

## Целевая модель

Beget Shared не умеет Node в рантайме → в проде только статика + CGI. Никакого
Node-сервера в прод: fullstack-фреймворки (Next и пр.) отклонены. При задачах,
которым нужен Node (CRM-интеграции сложнее вебхука) — пересмотреть хостинг (VPS),
не вставлять Node в этот деплой-путь.

## Пайплайн выката

`astro build` → `rsync dist/` по SSH → корень сайта (включая `cgi-bin/contact.py`
и `.htaccess`). Разовая настройка: CGI для `.py` включается в панели Beget —
проверить до первого выката формы.

## Секреты

- Никогда не коммитить `.env` — только `.env.example`. (Правило CLAUDE.md.)
- Прод-секреты — в `/home/<user>/.env-ssq` вне docroot; путь задаёт
  `SSQ_ENV_PATH`; переменные окружения имеют приоритет над файлом.
- rsync секретный файл не трогает — создаётся вручную один раз.
- Если сгенерирован новый токен Telegram-бота: не печатать, не коммитить,
  дать владельцу команду для ручного размещения в `.env-ssq`.

## CGI-эндпоинт `cgi-bin/contact.py`

Полный контракт эндпоинта (валидация, honeypot, rate-limit, доставка в
Telegram, 400/502) — в скилле `.claude/skills/ssq-form-cgi/SKILL.md`;
в этом скилле деплой-специфика: эндпоинт уходит в деплой вместе с `dist/`,
(`cgi-bin/contact.py` + `.htaccess` с `AddHandler cgi-script .py` + `ExecCGI`),
CGI для `.py` включается в панели Beget до первого выката.

## Откат (rollback)

- Перед выкатом содержимое docroot складывается в `~/releases/backup-<timestamp>/`
  (`rsync --backup --backup-dir`).
- Откат = обратный rsync из backup-каталога.
- Симлинки неприменимы: docroot Beget Shared фиксирован; каталог-симлинк
  сломает путь сайта.

## Гейты выката (последовательность)

1. `astro check` типы-чистый — ошибки типов = блокер (решение владельца
   2026-10-18). Запускать как `npm run check`: контракт скрипта — `"check":
   "astro check"` в целевом `package.json` (в `site/`, появится на шаге 1
   каркаса; скрипт не работает, пока каркаса нет — факта).
2. `astro build` проходит — не проходит = блокер.
3. Prettier (`npm run format:check`) — чисто.
4. ESLint (`npm run lint`) — без ошибок (решение 2026-10-18 в docs/memory.md).
5. Форма не выкатывается без политики ПДн и реквизитов ИП (152-ФЗ) — правило
   спеки §6.3; политика у `/legal/privacy/`, форма ссылается, чекбокс обязателен
   (форма не выходит в прод раньше политики и реквизитов).
6. claude-security:scan перед релизом; CONFIRMED-находки = блокер.

## После выката — smoke-тест из прода

7. Тестовая заявка через форму из прода реально доходит до Telegram (спека §9,
   [test-case.md](../../docs/test-case.md) шаг 10). Сбой доставки виден сразу:
   эндпоинт отвечает честным `502 {ok:false}`, а не маскирует успех.
8. `smart-sq.ru` отвечает 301-редиректом на smart-square.ru.
