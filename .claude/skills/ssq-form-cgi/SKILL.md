# Форма заявок SSQ-site — контракт

Источники решений: `docs/specs/ssq-site-stack-design.md` (§6) и `docs/architecture.md`
(«Форма и заявки»). Докс главнее скилла; при расхождении — править оба и сказать
владельцу. Проверки формы после любых правок: qa.md, раздел «Форма».

Критичность: форма — kpi-функция (заявки = деньги проекта); единственная
серверная логика в проде. Контракт формы не меняется при смене хостинга, меняется
только тело доставки (CRM позже).

## 6.1 Клиентская часть (`/contacts/` + CTA-секции)

Поля:

- имя — обязательное
- телефон — обязательное, формат РФ (маска)
- комментарий — опциональное
- чекбокс согласия на обработку ПДн — обязательный, ссылка на `/legal/privacy/`
- honeypot `website` — скрытое поле, видит только бот
- контактные данные (телефон-фоллбек) — только из `src/data/site.json`, не хардкод

Поведение:

- `novalidate`, собственная подсветка ошибок (не браузерные тултипы)
- состояния формы: `idle → sending → ok` (успех — форма сбрасывается) /
  `error` (текст ошибки + телефон из site.json как альтернативный канал)
- отправка — POST на `cgi-bin/contact.py` с JSON

## 6.2 Серверная часть `public/cgi-bin/contact.py`

- Python 3, **только stdlib**; CGI на голом Python (не Passenger); `.htaccess`
  с `AddHandler cgi-script .py` + `ExecCGI`.
- Метод `POST`; принимает `application/json` или form-encoded.
- Ручная валидация → при нарушении `400 {ok: false, error: "..."}`: пустые
  обязательные, некорректный телефон, несогласие с чекбоксом. Текст ошибки —
  русский, дружелюбный.
- Honeypot заполнен → **маскированный успех**: ответ `{ok: true}`, заявка не
  доставляется. Никогда не выдаёшь боту реальный отказ.
- Rate-limit по IP: лимит `FORM_RATE_LIMIT_PER_HOUR` (по умолчанию 10/ч);
  счётчик — файл в `/tmp`. Превышение → отказ так же, как валидация.
- Доставка: POST в Telegram Bot API (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`),
  таймаут 5 с. При отказе доставки — **не маскировать успех**: `502 {ok: false}`.
  Тихая потеря заявки — самый дорогой баг этой системы: клиент думает, что
  отправил, заявка пропала.

## Секреты формы

- В репозитории — только `.env.example`; сам `.env` не коммитится никогда.
- В проде — файл вне docroot: `/home/<user>/.env-ssq`, путь задаётся
  `SSQ_ENV_PATH`; переменные окружения имеют приоритет над файлом.
- Новые значения токена — дать владельцу команду для ручной установки в
  `.env-ssq`, не печатать и не коммитить.

## Развитие

Подключение CRM = замена тела доставки в `contact.py`; клиентский контракт
(`ok/error`, 400/502, поля формы) не меняется — поэтому валидация и состояния
формы фиксированы здесь, а не в деплой-документации.

## Проверки после правок формы (qa.md)

1. Пустые обязательные — подсветка, отправки нет
2. Заполненная + чекбокс — заявка приходит в Telegram
3. Без чекбокса — отправка блокируется
4. Honeypot заполнен — заявка не доставляется, ответ маскируется под успех
5. Повторные отправки с одного IP чаще лимита — отклоняются
6. Эндпоинт недоступен — пользователь видит ошибку и телефон, а не «тихую» потерю
